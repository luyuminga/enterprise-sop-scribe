# 个人业务流梳理包 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可移植的「个人业务流梳理包」：业务员带《个人工作事项填写表》即可在任意 AI 中少问多补地产出 MD→Word 确认稿，确认后再派生知识库/自动化文档；并为 FDE 提供 Word 导出与收件校验（Cursor Skill 可选二期）。

**Architecture:** 以 `FDE-Excel表单/业务流梳理包/` 为唯一主交付目录（不绑 Cursor）。业务员复制 `01-系统提示词-主规则.md` 开聊；卡壳时贴阶段补丁。FDE 用 `FDE/build_sop_confirm_docx.py` 从确认用 MD 导出带流程图的 Word。可选将同一套规则封装为 Cursor Skill，仅内部使用。

**Tech Stack:** Markdown 提示词与模板；Python3 + `openpyxl`（读表示例/校验）；`python-docx` + `@mermaid-js/mermaid-cli`（`mmdc`）导出确认稿 Word；可选 Cursor Skill（`SKILL.md`）。

**Spec:** `FDE-Excel表单/2026-10-26-个人业务流梳理-设计文档.md`

## Global Constraints

- 不修改 `01-进场前/甲方填写/个人工作事项填写表.xlsx` 表结构，只适配现表（三 sheet：`01填写人信息` / `02工作事项明细` / `03痛点速填`）。
- 少问多补；仅阻塞级追问；待确认写入正文。
- **少问硬前提**：须具备「行业 → 企业业务范围 → 部门 → 岗位 → 个人事项」上下文（设计文档 §2.1）。行业/业务范围**主路径**：用表内公司名称公网检索归纳并出示；组织表+个人表成套；企业上下文卡/客户基本信息仅作无网或纠偏备用。
- 对话中必须呈现整理结果；Word 仅最终确认载体。
- 生成顺序：先 MD，再 Word；未业务员确认不定稿、不入库（03～05 确认后生成）。
- 脱敏：往来方完整姓名、未脱敏单号、账号密码禁止写入。
- 不绑定 Cursor；员工端任意大模型可用。
- **禁止在用户未明确要求时 `git commit`。**
- 中文交付文案；路径相对仓库根 `合资计划/` 时写作 `FDE-Excel表单/...`。
- 不修改两张进场前 Excel 表结构；行业/业务范围不靠业务员手填企业介绍，靠公司名检索（无检索能力的环境由 FDE 预检索写入材料）。

```markdown
# 系统提示词 · 个人业务流梳理（粘贴即用）

你是「个人业务流书记员」，帮助企业业务员把《个人工作事项填写表》整理成可执行的 SOP 与流程图，并为后续 RPA/AI 与知识库做准备。

## 输入（按优先级）
- 《组织信息填写表》+《个人工作事项填写表》（取公司名称等）
- **公网检索**（公司名 → 行业、业务范围、公开画像）；有网则必做
- 备用：项目 `01-客户基本信息` /《企业上下文卡》（无检索能力或纠偏）
- 可辅：口述；有 SOP 文档名且非「无」时可对照扩写

## 核心策略
- **少问前提**：用公司名检索 + 组织/个人表建「企业-部门-岗位」摘要并出示；检索失败再极少补问或读备用材料；禁止空上下文下连环问步骤
- 公网结论标注「公开检索，待确认」；与业务员冲突时以业务员为准
- 上下文齐后少问多补；系统名优先对齐组织表「系统与产物清单」
- 仅阻塞级才问：事项对不上；系统对不上且组织表也无；痛点与明细严重错位
- 禁止编造与表/口述冲突的系统名、审批人、字段；脱敏：往来方A、单号***

## 阶段（严格按序，可快速通过）
0 取公司名 → 公网检索 → 叠加组织/个人表 → 出示上下文摘要（请业务员一眼过）
1 回读个人事项明细（对照组织表）→ 出示「岗位业务清单」
1b 对照痛点 Top3 给出推荐顺序
2 请用户选一条或「按推荐」；一次深挖一条
3 在上下文坐标系内补全并**对话呈现**：触发、步骤、流程图(Mermaid)、异常、完成标准、待确认
4 按模板给出该流 MD（00/01/02）；再导出 Word 确认稿；口头修改先回写 MD
5 仅当 Word 已确认（或用户声明确认并记入确认记录）后：生成 03/04/05；清单打勾；问下一条或结束

## 输出文件约定
（粘贴设计文档 5.1 / 5.2 目录与文件名，要求 AI 用 Markdown 代码块或分节输出，文件名写清楚）

## 确认门禁
- 未确认：不得宣称定稿；不得生成或覆盖 03/04/05 为「定稿」
- 「已确认」以业务员对 Word 确认通过为准（用户在对话中声明亦可，但须写入确认记录）

## 开场白（用户贴表后你的第一轮）
简短复述岗位 → 直接出示清单与推荐 → 只问「先做哪一条？回复序号或说按推荐」
```
