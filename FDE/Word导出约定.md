# Word 导出约定（流程确认稿）

## 目的（三个第一要义）

1. **给业务员**：打开 Word **第一眼是业务流程图**，直观判断梳理对不对。  
2. **给 FDE**：先看懂全貌，再下钻 MD / 触点 / 自动化分析。  
3. **给开发**：图上节点为 `角色·系统·动作`，配合 MD 里节点说明/触点字段，**能按图拆开发任务**（空心大步骤图不合格）。

## 文档阅读顺序（固定，不可调换）

| 顺序 | 章节 | 作用 |
|------|------|------|
| 0 | 标题 + 事项标识（名称/岗位/部门） | 知道是哪一条 |
| 1 | 确认提示（短） | 提醒：请先对图、再对文字 |
| 2 | **一、业务流程图** | **主视觉，版面最大**；图优先于一切说明文字 |
| 3 | 二、业务背景 | 目的、范围、SIPOC、触发、完成标准 |
| 4 | 三、操作步骤与协作 | 步骤表、RACI、交接点 |
| 5 | 四、异常、规则与待确认 | 例外与【待确认】 |
| 6 | 文末确认提示 | 再次收口 |

禁止：先堆长文背景、把流程图挤到文末或附录。

## 输入

某 `flows/0N-{短名}/`：

- 必选：`01-业务流程图.md`（含 mermaid）、`02-SOP作业指导书.md`
- 可选：`00-事项原文与确认.md`（补元信息）

## 输出

`02-SOP作业指导书-确认稿.docx`（可加 `-vN`）

## 命令

```bash
pip install python-docx pillow
# 强烈建议安装以出图：npm install -g @mermaid-js/mermaid-cli

python3 build_sop_confirm_docx.py \
  --flow-dir "/path/to/flows/01-示例事项" \
  --out "/path/to/flows/01-示例事项/02-SOP作业指导书-确认稿.docx"
```

无 `mmdc` 时仍生成 Word，流程图节放步骤列表/源码占位，并 stderr 警告——**不得省略「一、业务流程图」章节**。

## 版式

- A4；确认提示加粗  
- 流程图插图尽量宽（约版心宽度），独占「一、」节  
- 背景与步骤用黑体节标题，正文宋体小四
